# voxel-open-world

Открытый мир: регионы 32 м, streaming, LOD, floating origin, задел под кооп.

## Сначала прочитай

- `docs/ENGINE_PLAN.md`, разделы 4.4 (масштаб), 5.3 (память), 5.5 (формат/стриминг), 4.3 (кооп).
- `AGENTS.md` — бюджеты и границы.

## Инварианты

- Регион — 32×32×32 м. Верхний уровень — 3D-текстура ID региона (`R32_UINT`, 0 = пусто); дескриптор региона ссылается на brick-index 16³ и LOD-данные.
- Для 8×2×8 км: 256×64×256 = 4.2M записей = 16 MB top-level. 16 км — считать отдельно, не предполагать.
- LOD-кольца: LOD0 0–48 м (12.5 см), LOD1 48–160 (25 см), LOD2 160–512 (50 см), LOD3 >512 (1 м/impostor).
- Near-field — единственный полностью редактируемый/физический/GI-слой. Far-field — coarse, streamed, разрушение грубое или отложенное.
- Маленький уровень — streaming выключен, все регионы LOD0; тот же код, другой конфиг.
- CPU-координаты — f64/локальные; рендер — camera-relative; floating origin, ребейз при 4–8 км. GPU не видит больших мировых координат.

## Residency

Состояния региона: `Unloaded → Loading → Ready → Dirty → Evicting → Unloaded`.

- LRU-вытеснение; dirty-регионы закреплены до сохранения.
- Кольцо предзагрузки вокруг игрока + приоритет по видимости/расстоянию.
- Бюджет загрузки 8–16 MB/кадр; worker-пул читает/распаковывает, главный поток только staging ring.
- Никакого дискового I/O и декомпрессии в кадре.
- При переполнении VRAM сначала резать дальний LOD, потом вытеснять регионы.

## Streaming и сохранение

- `.vxl`: manifest + регионы + LOD + zstd; базовый регион и delta-log правок отдельно.
- Запись атомарная (temp + rename), компакция периодически.
- Детерминированный порядок загрузки/обхода — для сохранений, сети, тестов.
- Прогресс/ошибка загрузки — в UI, не молчаливый лог.

## LOD

- Понижение: доминирующий материал + средний цвет; не «первый воксель».
- Переходы — dithered + TAA; не менять LOD региона внутри кадра.
- Far-field не участвует в физике/GI; тела спят/заморожены.
- LOD bias может двигать frame governor; не менять каждый кадр.

## Floating origin

- Мир на CPU в f64 или локальных координатах; камера/рендер — относительно origin.
- Ребейз при |pos| > 4–8 км: сдвинуть origin, пересчитать camera-relative матрицы, не трогать воксели.
- Физика Jolt — в локальных координатах; не кормить её мировыми f64.
- Тесты: объект на 8 км, рендер и коллизия не «дрожат».

## Кооп-задел

- Команды `{tick, seq, region, op, brush, material, seed}`; фиксированный шаг 60 Гц; стабильные ID.
- Interest management по 32-м регионам; сервер авторитетен позже.
- Join-in-progress: снапшот + компактный лог команд; не пересылать воксели.
- Физика: игрок — предсказание, обломки — косметика/репликация.
- Non-goals первой версии: rollback, матчмейкинг, античит, выделенные серверы. Не тащить сеть в hot path single-player.

## Ловушки

- Регион на границе мира: ID 0 конфликтует с «пусто» — использовать отдельный sentinel/диапазон.
- Швы LOD/регионов и «дыры» на стыках; тестировать границы.
- Слишком агрессивное вытеснение → постоянные подгрузки; гистерезис.
- Dirty-регион вытеснен до сохранения → потеря правок.
- Стриминг в главном потоке → столы; только worker + staging.
- Один и тот же регион загружен дважды (LOD0 и LOD2) → лишняя VRAM.
- Ребейз во время физического шага → телепорт тел; ребейзить между шагами.

## Бюджеты

- VRAM ≤6.5 GB всего; воксели ≤2.5 GB; 100–200 регионов resident.
- Квартал загружается ≤5 с (NVMe); открытый мир — без столов >1 кадра.
- Правка вокселя — без фризов >2 мс.
- 144 fps в типовых сценах, 100–120 в тяжёлых, 60 floor.

## Тесты

- Загрузка/выгрузка региона, повторная загрузка, dirty + save.
- LOD-переход: нет дыр, нет двойной загрузки.
- Floating origin: 8 км, камера/физика/тени стабильны.
- Стриминг-стресс: быстрый полёт, нет столов >1 кадра.
- Кооп: одинаковый лог команд → одинаковый хеш мира.
