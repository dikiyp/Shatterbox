# Задача: от «свет и разрушения — шлак» к играбельной сцене с домами

Прочитай `AGENTS.md`. Загружай по этапу: Э0–Э1 — `voxel-render`; Э2–Э3 — `voxel-physics`, `voxel-world`; Э4–Э6 — `voxel-vfx`. `voxel-open-world` не загружать.

Работай **строго по этапам Э0→Э6**. После каждого этапа остановись и отчитайся по формату в конце файла. Не начинай следующий, пока я не скажу «дальше». «Готово» не пиши без подтверждённого результата; цифры замеров — только из моего вывода. GPU-замеры запускаю я, ты даёшь команды.

## Общие ограничения

- Не добавлять зависимости без обоснования.
- Не менять целевые показатели (`AGENTS.md` §3) и инварианты (§4).
- Правки вокселей — детерминированные команды; частицы, вспышки, тряска — косметика, не влияют на мир.
- Не возвращать `voxel_bevel` и пирамиду 4 м. Джиттер возвращается только в Э1.
- Любое утверждение аудита проверяй по коду перед правкой; если не подтверждается — скажи.
- Рефакторинг шире этапа — сначала спроси. Результаты замеров вношу в `docs/ENGINE_PLAN.md` раздел 10 я, ты предлагаешь текст.

## Э0. Быстрые баги (минимальные правки)

1. `light_axis`: порядок полей Rust ↔ WGSL (`lighting.wgsl`, `light_shadow.wgsl`, `renderer.rs`); везде явные `min_binding_size`; тест/assert на размер и смещения.
2. SSR отвязать от бита SSGI (отдельный флаг эффекта).
3. `probe_dirty` при ресайзе и смене scale.
4. Чтение отражений в `lighting` только если GI-проход был выполнен (иначе нейтральное значение).
5. Рисовать новейшие 64 обломка, а не старейшие; согласовать бюджет симуляции (320) с лимитом рендера, чтобы разница была видна в оверлее.
6. `light_shadow` не диспатчить при 0 источников; `RenderStats.light_count` считает все типы.

Критерий: capsule/rect свет виден; выключение SSGI не выключает SSR; после 5 ракет видны новые обломки.

## Э1. Свет (бывший M1)

1. Подтверди причину «тени обрезаются за пределами сферы»: переключай `SHATTERBOX_EFFECTS` и `SHATTERBOX_QUALITY`, смотри таблицу диагностики в `voxel-vfx`; назови файл и константу.
2. Depth/normal-aware апсэмплинг для AO, GI, fog, reflection вместо `pixel/2` nearest.
3. Temporal: вернуть Halton-джиттер вместе с rejection по глубине/нормали, reactive mask на изменённых кирпичах и пикселях обломков, корректный `history_reset`. A/B с текущим состоянием.
4. Шов AO каждые 2 м: сосед за границей кирпича считается корректно.
5. Timestamps на `shadow`, `light_shadow`, `gi`, `fog`, bloom; вывод в оверлей.
6. Затухание локальных источников — плавное окно, без жёсткой отсечки.
7. Дай 4 позиции камеры (координаты, yaw/pitch) и команды запуска для до/после.

Критерий: нет видимой границы теней и блочных квадратов, тени/AO не мигают, GPU ms по проходам видны в оверлее.

## Э2. Физика «про мир» (главный блокер)

1. Статический коллайдер из вокселей: секторы 8 м (план 7.2), greedy box merge, ленивое создание вокруг активных тел, dirty → асинхронная пересборка. Убрать пять захардкоженных боксов (`game.rs`).
2. `compound_boxes`: occupancy-тест чанков (минимум); по возможности один hull на связную компоненту. Масса через `MassAndInertia` с посчитанным тензором.
3. 6-связный flood fill в грязном регионе, отсоединение компонент без якоря, превращение в динамические тела (план 7.3, закон сохранения вокселей).
4. Интерполяция тел между 60 Гц шагами (prev/curr, lerp/slerp).
5. Разрушение: инкрементальное обновление occupancy групп/регионов вместо `rebuild_occupancy()` на всё; батч-аплоад правок в staging; тяжёлая часть (carve, кластеризация, создание тел) — в worker pool или хотя бы вне кадра рендера; clamp радиуса команды.
6. Ракеты шагаются фиксированным шагом 60 Гц; seed детерминирован.

Критерий: ракета в пол оставляет кратер, обломки в него падают, игрок падает в кратер; кусок не висит на невидимом углу; отсоединённый кусок конструкции падает; нет фриза на выстрел (замер).

## Э3. Коллизия игрока

Capsule sweep по осям без туннелирования (тест 50 м/с), скольжение с нормалями, snap-to-ground, step-up 0.55 м только на земле, потолок гасит вертикальную скорость, диагональ не быстрее, мгновенный учёт разрушения, выталкивание из геометрии вместо вечного застревания. Гравитацию объектов привести к одной (согласуй с моим выбором для игрока, спроси).

## Э4. Сцена: два двухэтажных кирпичных дома

См. раздел «Сцена теста разрушения» в `voxel-vfx`. Режим `SHATTERBOX_SCENE=houses`, «белая студия» остаётся. Лимит 12 point lights: по 3–4 на дом, запас под FX, остальное emissive. Тест: подрыв несущей стены отсоединяет вышележащую часть; нет плавающих блоков в начальном состоянии.

## Э5. Ракета и базука

Видимая ракета (воксели, огненный хвост, point light, дымовой след), детонация через `DestructionSystem::explode`; базука от первого лица (покачивание, откат, дульная вспышка, отвод у стен); резерв слотов инстансов (общий лимит 64). Тест: детонация в точке прицела.

## Э6. Сочные взрывы

Стек из `voxel-vfx`, по шагам с замером после каждого: вспышка и тряска → дым и пыль → огненный шар и искры → осколки → копоть и кратер → `ExplosionEvent`. Критерий: FX ≤1.0 мс GPU, серия из 5 ракет не ниже 60 fps.

## Не сейчас

GI (цветной bounce, направленные пробы, sky cubemap), AgX, `MAX_GPU_BRICKS`, сжатие кирпичей, упаковка G-буфера.
