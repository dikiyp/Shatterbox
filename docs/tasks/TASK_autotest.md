# Этап Э−1. Автотест-харнесс (делается ПЕРВЫМ, до остальных этапов)

Прочитай `AGENTS.md` и скилл `voxel-autotest`. Цель: чтобы ты сам запускал игру, ловил ошибки, снимал скриншоты и мерил, а пользователь тестировал только вкус. Остальные этапы (Э1 ч.1, Э1Б, Э2…) не начинай.

## Что сделать

1. **Режим сценария.** `shatterbox.exe --scenario <имя> --out <папка> [--scale F] [--effects N] [--seed S] [--frames N]`. Парсер аргументов — стандартная библиотека или уже имеющийся крейт; новые зависимости — только с обоснованием.
2. **Сценарии** в `scenarios/*.ron` (формат — как в скилле): `camera`, `time_of_day`, `effects`, `wait`, `fire`, `screenshot`, `assert`, `exit`. Создай `smoke`, `fire_wall`, `fire_series`, `lighting_set` (4 позиции), `edge_set`.
3. **Фиксированное время**: sim 60 Гц, фиксированный seed, синтетический ввод вместо реальной мыши/клавиатуры, без vsync; количество кадров задаётся сценарием.
4. **Скриншоты движка**: рендер в offscreen-текстуру выходного разрешения (2560×1440), readback, PNG. Для PNG допустим крейт `png` (маленький, без тяжёлых зависимостей): напиши обоснование в отчёте. Скриншот не из свопчейна и не OS-захват.
5. **report.json** с полями из скилла. Для `gpu_ms` по проходам используй существующие timestamps; для проходов без них — добавь (`shadow`, `light_shadow`, `gi`, `fog`, bloom).
6. **Ошибки валидации**: считай через `on_uncaptured_error`/error scopes wgpu и ERROR-записи tracing; при любой — код выхода ≠ 0 и запись в `report.json`. Фоллбэк на встроенные шейдеры при ошибке валидации тоже считается ошибкой.
7. **Watchdog**: если сценарий идёт дольше `--timeout` (по умолчанию 120 с), процесс завершается с кодом 3.
8. **`shatterbox-tools diff a.png b.png`**: среднее абсолютное отклонение, % изменённых пикселей, diff-PNG.
9. **GPU smoke-тест в `cargo test`**: создание всех пайплайнов на реальном wgpu-устройстве, с пропуском при отсутствии адаптера (ловит класс ошибок «min_binding_size/layout» без запуска игры).
10. Первые автоматические проверки: `assert_hit_matches_render` и `assert_voxel_conservation`.

## Ограничения

- Не менять рендер, физику и визуал; харнесс только снимает и измеряет.
- Режим сценария не должен менять поведение обычного запуска.
- Для фиксированного времени допускается отдельный флаг `--fixed-time`; в обычной игре dt реальный.

## Как проверить себя (обязательно, сам)

1. `cargo fmt`, `clippy`, `cargo test --workspace` без ошибок.
2. Запусти `smoke` с таймаутом по шаблону из скилла. Приложи содержимое `report.json` и список PNG.
3. Запусти `fire_wall`, посмотри скриншоты (если умеешь читать изображения) и опиши, что видишь.
4. Запусти `smoke` дважды с одним seed, сравни PNG через `diff`: отклонение должно быть около нуля.
5. Если что-то из этого тебе недоступно (нет окна/GPU/просмотра изображений) — скажи прямо, что именно, и какие результаты поэтому не получены.

## Формат отчёта

1. Что сделано.
2. Файлы.
3. Тесты и результат `fmt`/`clippy`/`test`.
4. Реально выполненные запуски: команда, код выхода, ключевые числа из `report.json`.
5. Что не получилось или недоступно.
6. Риски и вопросы.
